# 02 — The decision model in the Confidence Level (`confidence-3`)

**Spec:** [../spec.md](../spec.md) · **Blocked by:** 01 · **Status:** ready-for-agent

**What to build:** When the decision model is switched on, every Analysis sends one request per Premise (PL: Przesłanka) to the decision model TypeSafe "Jev" and gets three answers: the kind of post (`rodzaj_wpisu`), the declaration of ownership (`deklaracja`) and the warning (`ostrzezenie`). Code turns the answers into the status, the kind and the points of the Premise with fixed thresholds and the `confidence-3` rule table. The model never sees the full name, e-mail or messenger ID of the investigated person, never creates a link to the person that code did not find, and never outputs the Confidence Level. When the model is off (the default, no API key needed) the Analysis runs on the `confidence-2` rules of task 01. When the model is on but does not answer for a Premise, that Premise is assessed by the keyword rules and the report gets a new Report Limitation. Every Analysis saves its own model answers, the pinned model version, the question-set version and the assessment mode; answers are never reused between Analyses. The comparison of two Analyses marks a changed Confidence Level with the same Mentions as "model assessment changed, no new Mentions". The new fields go into the API contract (`./scripts/api-sync.sh`). The golden set of task 01 is also scored by `confidence-3`: in CI with model answers given as data or by a stubbed HTTP endpoint, and once by hand against the real model, never in CI. No frontend change (task 03).

## Decisions that apply

- **Boundary (D4, D6, DJ1-001):** code answers "whose?" (address detection and validation, Excluded Addresses, the link to the person, independence of sources, arithmetic of points). The model answers only "what does this text say about the address?". It is never asked "is this person X". When code sees no link and the model sees a declaration, the Premise gets 0 points and "Do weryfikacji"; the model never makes the link.
- **The model (D5):** TypeSafe "Jev", a decision model that takes a state and typed questions and returns only numbers and labels, no text (unchecked (handoff)).
- **Port (D12, spec "Modules"):** one interface in `analysis/AnalysisContracts.kt`, "assess these Premises", that returns per Premise either the three answers with raw probabilities, or "no answer". Two adapters: the model client, and a rules-only adapter that answers "no answer" for every Premise and is used when the model is off. The orchestrator and scoring only know the port.
- **How to call the model (D12):** first, on a separate branch from `master`, try for at most one hour to upgrade the backend to Spring Boot 4.2 and use the Spring AI System One module. By the handoff, `spring-ai-starter-model-systemone` 2.1.0 needs Spring Boot 4.2 (unchecked (handoff)). The attempt passes only when `./gradlew check integrationTest` is green on that branch. If it does not pass in one hour, write a thin own client on the JDK `HttpClient`, like `EthRpcContractCodeSource` in `service/ContractCodeSources.kt`, and keep Spring Boot 4.1.2. Either way the client sits behind the own port, with the base URL and the model name in configuration (5.6). Report the result of the attempt to the lead; whether `master` moves to Spring Boot 4.2 is the lead's decision.
- **Off by default (D13):** switched on only by configuration together with an API key from an environment variable. Without a key the application works on rules alone. Configuration (**P20, proposal the lead may change**): `app.assessment.model.enabled` (default `false`), `base-url`, `model` (pinned snapshot), `timeout`; the API key from the environment variable `ASSESSMENT_MODEL_API_KEY`, never written in a file. Switched on without a key: one `WARN` at start-up, and the Analysis runs on rules only.
- **One request per Premise, three questions, each answer saved separately (D8):**
  - `rodzaj_wpisu`, choice: own declaration / sale or settlement / discussion / mass comment;
  - `deklaracja`, yes/no: the author of the text presents the assessed address as their own (about the author of the text, not the investigated person);
  - `ostrzezenie`, yes/no: the text tells readers not to use or trust the assessed address.
  - Question-set version `premise-questions-1` (**P21, proposal the lead may change**). Any change of the wording is a new question-set version.
- **What is sent, the state (spec "Model state", P15, P16):** the masked text window of the Premise, the assessed address, "author is the investigated person: tak / nie / nieznany", the number of addresses in the Mention, and the service host. Nothing else from the Case. Keys in Polish: `tekst`, `oceniany_adres`, `autor_jest_badana_osoba`, `liczba_adresow_we_wpisie`, `serwis` (**P16, proposal the lead may change**). The host is sent, never the full URL (P16).
- **What is never sent:** the full name, the e-mail and the messenger ID of the Case (D4), the Case id, the other identifiers as separate fields, the URL, the Analysis results. Before sending, code replaces in the window the Case's e-mail, messenger ID and full name, and every other e-mail address, with "[e-mail]", "[komunikator]", "[imię i nazwisko]" (**P15, proposal the lead may change**; the nickname and login stay in the text, the lead should confirm). Premises of Rejected and Excluded Addresses are not sent (P18).
- **Requests (**P18, proposal the lead may change**):** in parallel on virtual threads, one per Premise, a timeout of 5 s per request, no retry.
- **Thresholds in code (D9, P12, P28):** for `deklaracja` and `ostrzezenie`, 0.7 or more is yes, 0.3 or less is no, between is undetermined. For `rodzaj_wpisu` the top option counts when its probability is at least 0.5, otherwise the kind is undetermined (**P12, proposal the lead may change**). The yes/no word follows the thresholds, not a rounded number (P28).
- **`confidence-3` rule table (D9, spec "Rule table per version"),** in this order for one Premise (**P13, proposal the lead may change**):
  1. No code link to the person: 0 points. If `deklaracja` is yes: status "Do weryfikacji" (D6, S5); otherwise dismissed "no link to the person". Exception: a page under the profile with a known other author is a link fact in `confidence-3`; there `deklaracja` yes gives "address declared by another person", otherwise "no link to the person" (**P7, proposal the lead may change**; S2).
  2. E-mail of another person: dismissed "e-mail of another person", code only, as in `confidence-2`.
  3. `ostrzezenie` yes and `deklaracja` not yes: dismissed "warning".
  4. `deklaracja` yes and the author is known and is not the person: dismissed "address declared by another person".
  5. `deklaracja` yes and `ostrzezenie` yes and the author is the person: withdrawn own address (D10). It counts like an own declaration (80), status "Zaliczona", with the note "Adres wycofany przez autora" on the Premise and the Justification sentence "Autor wpisu podał, że ten adres był jego, ale już go nie używa." (**P14, proposal the lead may change**; whether the points are reduced is open for the lead).
  6. Kind: own profile (code) stays 80. Otherwise the model's `rodzaj_wpisu`: own declaration 80, sale or settlement 60, discussion 40, mass comment 10. `deklaracja` yes alone does not raise the kind (G1 stays 60).
  7. Any undetermined answer that is still relevant: status "Do weryfikacji", counted at most as discussion (40); a mass comment stays at 10 (P13, D9, S4).
- **Same as `confidence-2` (task 01):** the base is the strongest kind among the counted Premises; +15 only for two Premises on different services, both at least discussion, with different address sentences (P8); an unclassified address is capped at 59 (P9); every applied rule carries the ids of its Premises (P10).
- **Who assessed what (D16):** link facts, e-mail, independence, cap and points are always `RULE`. Kind, declaration and warning are `MODEL` when the model answered for that Premise, otherwise `RULE` (keyword fallback). Code names `RULE` / `MODEL`, mode `WITH_MODEL` / `RULES_ONLY` (**P11, proposal the lead may change**).
- **Fallback (D13, spec "Fallback"):** per Premise. A Premise without an answer is assessed by the `confidence-2` rules and labelled `RULE`. The Analysis keeps its status. New Report Limitation `MODEL_ASSESSMENT_UNAVAILABLE`, added once, when at least one Premise fell back while the model was on; not added when the model is off by configuration (**P19, proposal the lead may change**). Text for task 03: "Model nie ocenił części lub wszystkich przesłanek; te przesłanki oceniono samymi regułami."
- **Scoring stays pure (D9-001 amended, P17):** the orchestrator calls the port after exclusion and before scoring; the answers go into `ScoringInput` as plain data. `ConfidenceScoring.score(...)` makes no external call, so the same saved Premise assessments always give the same Confidence Level and the same Justification (D17).
- **Algorithm version (**P22, proposal the lead may change**):** `confidence-3` whenever the model is on, also on a full fallback; `confidence-2` when it is off.
- **Audit per Analysis (D18, P21):** `algorithmVersion` (exists), `assessmentMode`, `modelVersion` (as echoed by the server, else as configured), `questionSetVersion`. Per answer: the label or the yes/no value, all raw probabilities (every option of the choice), and the request id when the server returns one (**P21, proposal the lead may change**). Stored inside the Analysis record (the `AnalysisResult` embedded in `AnalysisRecord`), not on the shared Mention document (spec "Analysis snapshot").
- **No reuse (D7, DJ1-001):** every Analysis asks the model again. No cache, no lookup of answers from an earlier Analysis.
- **Comparison (D7, P23):** a `CONFIDENCE_LEVEL_CHANGED` entry gets the flag `modelAssessmentChanged` when the Mention ids of both sides are equal and at least one of the two Analyses used the model; new comparability limitation `MODEL_VERSION_DIFFERS` (**P23, proposal the lead may change**). Proposed PL copy, for a later screen: "Zmieniła się ocena modelu, brak nowych wzmianek". API only; there is no comparison screen.
- **Justification (D17, P24):** still built from templates, never written by the model. New sentences for: dismissed by warning (model), declared by another person, "Do weryfikacji", withdrawn address, and one sentence when any Premise was assessed by the model: "Rodzaj wpisu i ostrzeżenia oceniono z pomocą modelu; punkty przyznały stałe reguły." (**P24, proposal the lead may change**). No numbers. The lead reviews the wording.
- **Logs (spec "Logs", `rules.md`):** counts, durations, HTTP status codes and request ids only. Never the text window, the state, a request body or a response body, and never the API key.
- **Golden set (P26):** the versioned fixture `golden-set-v1` of task 01 gets the `confidence-3` expected bands and canned model answers. The measurement against the real model is manual and opt-in, needs the API key, is never part of CI, and its result table is kept for the demo (**P26, proposal the lead may change**).
