# D9-006: The Justification is a template text; report contract `justification: String` + `mentions`

- **Status:** accepted; the contract change affects the frontend (E5, V13)
- **Date:** 2026-11-21
- **Type:** implementation of the frontend decision of 2026-11-21; contract change
- **Source:** frontend decision of 2026-11-21 (Case details design): "the Justification is a short plain-language text built from a template of the scoring rules that applied, not written by an AI model; no numbers; the report does not show the scoring breakdown or the algorithm version"; open point "wording of the template, one sentence per scoring rule (V13)"; mentor question 6; cheat sheet KROK 4; ADR 0001 ("Justification is a list of MentionResponse")
- **Proposed by:** AI agent (Claude)
- **Approved by:** Maksym U., grilling session 2026-11-21 (wording, field names, keeping the breakdown in the API)

## Problem and context
The issue said "references to Mentions only, no text". The frontend decision of 2026-11-21 reverses that: each Attribution needs a ready text next to the Confidence Level and its Mentions. The glossary and epic E3 are updated on `feature/FRONTEND` (not on this branch, to avoid a conflict).

## Options considered
Contract: `justification: String` and the Mention list renamed `mentions` (glossary name for the text), or keep `justification: List<MentionResponse>` and add `justificationText`. Breakdown: keep `scoringRules` and `algorithmVersion` in the API (UI hides them) or remove them from the report.

## Decision
- **Text:** one Polish sentence per applied rule, in the declaration order of `ScoringRule`, joined with a space. `{hosts}` is the comma-separated, sorted list of URL hosts (without `www.`) the rule is based on. No base values, contributions or percentages. Not generated by AI.

| Rule | Sentence |
|---|---|
| `ENTERED_BY_ANALYST` | Adres został wpisany przez analityka jako dane sprawy; samo wpisanie nie jest dowodem. |
| `OWN_PROFILE` | Adres został opublikowany na profilu badanej osoby ({hosts}). |
| `SALE_OR_SETTLEMENT` | Adres podano w ogłoszeniu sprzedaży lub w kontekście rozliczenia ({hosts}). |
| `DISCUSSION` | Adres pojawił się w dyskusji ({hosts}); taki ślad wymaga potwierdzenia drugim źródłem. |
| `MASS_COMMENT` | Adres pojawił się we wpisie konkursowym, promocyjnym lub typu giveaway ({hosts}), co jest słabą przesłanką. |
| `NO_PERSON_LINK` | Żadna wzmianka nie łączy tego adresu z danymi badanej osoby. |
| `INDEPENDENT_SOURCES` | Niezależne źródła różnego pochodzenia ({hosts}) wskazują na ten sam adres. |
| `SAME_SERVICE` | Kolejne wzmianki z tego samego serwisu nie są dodatkowym potwierdzeniem. |
| `COPIED_TEXT` | Wzmianka w innym serwisie powtarza tę samą treść, więc nie jest niezależnym potwierdzeniem. |
| `NICKNAME_ONLY` | Adres łączy z badaną osobą tylko nick lub login, które mogą należeć do innej osoby. |
| `WARNING_CONTEXT` | Wzmianki, w których adres występuje w ostrzeżeniu lub z prośbą, by go nie używać, nie zostały uznane za potwierdzenie. |
| `CONFLICTING_EMAIL` | Wzmianki zawierające adres e-mail innej osoby nie zostały uznane za potwierdzenie. |
| `CLASSIFICATION_UNAVAILABLE` | Nie udało się sprawdzić, czy adres należy do giełdy, kontraktu lub innej usługi. |

- **Storage:** the text is computed by the algorithm and stored in `ScoredAttribution.justification` inside the Analysis snapshot, so a reopened report shows the same words even if the templates change later (D25-001). Analyses stored before `confidence-1` read back with an empty text.
- **Contract:** `AttributionResponse.justification: String` (new meaning), `AttributionResponse.mentions: List<MentionResponse>` (the former list), `ExcludedAddressResponse.mentions` (renamed for one meaning per name). `scoringRules` and `AnalysisResponse.algorithmVersion` stay in the API for reproducibility (KROK 4, E6 comparison, E7 frozen scores); the UI does not show them.

## Consequences and risks
- `api-sync` regenerated `openapi.json` and the Orval client; no frontend code read the renamed fields.
- Host names may contain digits (`p2p.example`); "no numbers" means no scores or contributions.
- Supersedes the line "`Justification` is a list of `MentionResponse`, no text (E3)" of ADR 0001 and the "no text Justification" status of E3 (glossary update pending on `feature/FRONTEND`).

## Verification
`ConfidenceScoringServiceSpec` (exact sentences, order, hosts, no standalone numbers or `%`); `AnalysisReportSpec` (stored text and `mentions` in the report); `AnalysisFlowSpec` (text of the demo Attribution); `OpenApiContractSpec`.
