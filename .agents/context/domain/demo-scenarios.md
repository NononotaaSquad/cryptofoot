# Demo scenarios (synthetic data)

Thirteen fictional people in `backend/src/main/resources/fixtures/demo-v1.json` (`scenarios`), next to the original demo person Zenon Fikcyjny (`zenek_fx`, D9-008). Each one shows one behaviour of the tool: a correct result (happy path), a protection against a false lead (false positive), a known limit (false negative), an edge case, or a change between two Analyses of one Case. Mentors and the jury can click through them in the application.

- **Fictional on purpose.** The task requires anonymised or synthetic test data (section 3, E7.1). None of these people exist, and no real person's name is used.
- **Keyless addresses.** The people's own addresses are derived from public seeds (`olcys/demo-v1/scenario/...`; for S11 the payload is the first 20 bytes of SHA-256 of `olcys/demo-v1/scenario/S11/<forum|sale|new>`, for S12 of `.../S12/<own|impostor|commenter|campaign>`, for S13 of `.../S13/<sale|old|new>`), so nobody holds a key for them and they cannot belong to anyone. The ETH address of S1 (`0xE73A…20c6`) was checked on mainnet: no code, no transactions.
- **Real service addresses.** S2 and S12 use public exchange, mixer, fundraiser and contract addresses from the bundled label lists, because that is what the exclusion checks recognise. Both paste the Uniswap V2 router `0x7a25…488d`: its Etherscan tag `dex` is not an exclusion tag, so it is excluded as a smart contract only by the bytecode check.
- **Synthetic chain data.** Address Activity comes from `fixtures/demo-v1-activity.json` and is labelled "dane testowe".
- **Where it runs.** Synthetic data is on locally (profile `local`) and, after ADR 0003, on production. The expected values below assume the default configuration with the bytecode check on.
- **Frozen.** `DemoScenariosSpec` freezes every value below with the decision model off: algorithm `confidence-2` (rules only), Address Activity rules `activity-1`. With the model on, an Analysis is scored by `confidence-4`; the S12 and S13 values with the model are proven with canned model answers in the golden set (G17, G18), not by a live model call.

## How to run one

1. Open **Nowa sprawa**, fill in only the fields listed for the scenario, click **Rozpocznij analizę**.
2. In **Szczegóły sprawy**, expand each row of **Powiązania** and look at **Punktacja**, **Uzasadnienie**, **Wzmianki** and **Aktywność adresu**. Then check **Adresy wykluczone** and **Adresy odrzucone**.
3. For S11 and S13, click **Rozpocznij nową analizę** (or set the Schedule to every minute). The report of the new Analysis opens with **Zmiany od poprzedniej analizy** (frontend ADR-0014, PR #81). Each further rerun flips back, so it always has changes to show.

Locally every Analysis also lists `synthetic-broken` as an unavailable source (the "source unavailable" scene), so the status is **Częściowa**. On production that source is off (ADR 0003).

## With the bytecode check switched off

With `EXCLUSION_ONCHAIN_CHECK_ENABLED=false`, three results change:
- **S1:** the ETH address becomes an Attribution flagged "Nie sprawdzono, czy adres należy do serwisu". Its level is still 95%.
- **S2:** the Uniswap router is no longer excluded. It becomes an unclassified 40% Attribution with unavailable activity.
- **S12:** the Uniswap router is no longer excluded either (as in S2).
