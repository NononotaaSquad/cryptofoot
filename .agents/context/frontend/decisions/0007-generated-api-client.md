# ADR-0007: Generated API Client

**Status:** Accepted

**Context:**
Two backend and two frontend developers change the API contract during 24 hours. Hand-written types drift from the backend silently.

**Decision:**
The frontend talks to the backend only through a client generated by Orval 8 from the springdoc spec (`/v3/api-docs`). `lib/api/openapi.json` is a committed snapshot; `lib/api/generated/` (TanStack Query hooks and types) is committed and never edited by hand; `lib/api/client.ts` is the only hand-written fetch (base URL, throws on non-2xx) and `lib/api/api-error.ts` maps the error body to the typed `ApiError`. After a backend contract change, run `./scripts/api-sync.sh`: an integration spec (`OpenApiContractSpec`) writes `openapi.json` from the backend, then `npm run api:gen` runs. CI fails when the snapshot or `generated/` drift (see the `api-contract` skill). The backend error body is always `{ code: number, status: string, message: string, errors: { field: string | null, message: string }[] }` (`errors` filled only for 400 validation failures, exposed as `ApiError.fieldErrors`), where `status` is the status code followed by its name (e.g. `"404 NOT_FOUND"`, observed from the running backend on 2026-11-11); `ApiError.statusName` holds this value unchanged, so compare `httpStatus`, not `statusName`. Merge conflicts in `openapi.json` and `generated/` are resolved by regenerating from the merged backend.

**Consequences:**
- **Positive:** A backend contract change shows up as a type error
- **Negative:** Every contract change needs a spec refresh and `npm run api:gen`
